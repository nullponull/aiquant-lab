# aiquant-lab: Paper Trading が毎日落ち、失敗が自分を再生産していた (2026-09-10)

## 何が起きたか
`performance_summary()` が履歴 2 件未満のとき `{n_days, total_return}` **だけ**を返し、
呼び出し側は `summary["current_equity"]` を無条件に読む → 初日は必ず `KeyError`。
落ちる位置が `state.save()` の後・`git commit` の前 → ワークフローの "Commit state" に到達せず
**状態が保存されない** → 翌日も履歴 1 件から始まり同じ所で落ちる（09-07/08/09）。

## 正解
戻り値の形は入力で変えない。常に同じキーを返し、値の方で「まだ分からない」を表す（`n_days` で判別）。
回帰テスト `tests/test_paper_summary.py`（履歴 0/1/2 件でキー同一）。

## 学び
- **戻り値の形が入力で変わる関数**は、呼び出し側の分岐を増やすか、こうして落ちる。
- 失敗の「落ちる位置」を見る。保存とコミットの間で落ちると、失敗が自分を再生産する。
